### План выполнения от claude

Скрипт angristan в источниках проекта не описан, поэтому часть про него взята из моих общих знаний, без проверки по репозиторию. Перед запуском сверься с его README.

**Этапы в методичке:**

1. **Подготовка:** сеть (`/etc/network/interfaces`, DNS в `resolv.conf`), выход в интернет через NAT, `apt update/upgrade`.
2. **Установка пакетов:** `openvpn`, `easy-rsa`.
3. **PKI (Easy-RSA):** `make-cadir`, правка `vars`, CA, сертификат и ключ сервера, DH, `ta.key`, сертификат и ключ клиента.
4. **Настройка сервиса:** копирование ключей в `/etc/openvpn`, `server.conf` (`tls-auth`, `cipher`, `auth`, `user`/`group`).
5. **Сеть сервера:** `net.ipv4.ip_forward=1`, NAT (MASQUERADE) в `ufw/before.rules`, `DEFAULT_FORWARD_POLICY=ACCEPT`.
6. **Порт и firewall:** `ufw allow 1194/udp`, ssh.
7. **Запуск:** `systemctl start/enable openvpn@server`, проверка `tun0`.
8. **Инфраструктура клиентов:** `base.conf`, `make_config.sh`, генерация `client1.ovpn`.
9. **Настройка клиента:** пакеты NetworkManager, `scp` файла `.ovpn`, импорт и подключение.

**Что скрипт angristan может заменить (этапы 2–8):**

- Ставит `openvpn` и `easy-rsa` (версия 3.x, как у тебя).
- Строит PKI, генерирует `server.conf`, `tls-crypt` и клиентский `.ovpn` со встроенными сертификатами.
- Включает `ip_forward`, прописывает NAT и разрешение порта через iptables (не ufw), запускает сервис.

**Что остаётся вручную:**

- Этап 1: скрипту нужен интернет на сервере (NAT на pfSense, шлюз, DNS).
- Этап 9: перенос `.ovpn` на клиент и подключение.
- Правки под лабу: подсеть туннеля, `push route` для подсети за сервером, при необходимости маршруты на pfSense.

**Ограничения:**

- Скрипт интерактивный и задаёт значения по умолчанию (например, пушит DNS и весь трафик через VPN). Для объединения офисов эти настройки придётся править в `/etc/openvpn/server.conf`.
- Запускать лучше на чистой системе: твой `~/openvpn-ca` он не использует и создаст свой PKI в `/etc/openvpn/easy-rsa`.
- Если лаба предполагает ручную настройку, сверься с преподавателем: на защите могут спрашивать каждый этап (экзаменационные вопросы 20, 22, 24).

Этап 9 в методичке описан для Ubuntu Desktop 16.04 и подключения через NetworkManager. С профилем от скрипта angristan часть шагов другая.

**1. Проверь, что клиент подходит по версии:**

- Профиль использует `tls-crypt-v2` и AES-GCM, поэтому нужен OpenVPN 2.5+. На Ubuntu 16.04 из методички стоит 2.3, и профиль на нём не заработает.
- Возьми современный образ (Debian 11+, Ubuntu 20.04+). Версию смотри: `openvpn --version`.

**2. Установи клиент.** Один из вариантов:

- Консольный Linux: `apt install openvpn`
- Linux с GUI, как в методичке: `apt install network-manager-openvpn-gnome`

**3. Передай профиль на клиент.**

- На сервере файл лежит в `/root/client1.ovpn`.
- Через scp, если на сервере стоит ssh: `scp user@IP_сервера:/root/client1.ovpn ~/`. Вход под root по паролю в Debian обычно запрещён, поэтому скопируй файл на сервере в домашнюю директорию обычного пользователя (`cp /root/client1.ovpn /home/user/`).
- Если сети до сервера нет, выведи файл на сервере (`cat /root/client1.ovpn`) и вставь содержимое в `nano` на клиенте.

**4. Проверь и поправь строку `remote` в `client1.ovpn`:**

- Адрес должен совпадать с тем, что ты вписал в вопросе про NAT (IP сервера или IP pfSense). Исправь его в файле, если ошибся.
- Остальное в профиле править не нужно: сертификаты и ключи в нём уже встроены. Правки из методички (`user nobody`, `cipher AES-128-CBC`, `key-direction`, `script-security`) не применяй: они относятся к её `base.conf`, а шифр AES-128-CBC не совпадёт с тем, что настроил скрипт.

**5. Подключись.**

- Консоль: `openvpn --config client1.ovpn` (терминал занят, пока туннель жив).
- Фоном: скопируй файл в `/etc/openvpn/client/client1.conf`, затем `systemctl start openvpn-client@client1`.
- GUI: Edit Connections → Add → Import a saved VPN configuration → выбрать `client1.ovpn` → Save → включить VPN.

**6. Проверка:**

- `ip a show tun0` (адрес из 10.8.0.0/24)
- `ping 10.8.0.1` (сервер по туннелю)
- `ping` хоста из 172.16.11.0/24 (доступ в подсеть за сервером)

**7. Если клиент снаружи за pfSense:** нужен port forward 1194/UDP на pfSense в сторону сервера и разрешающее правило. Без него подключение не пройдёт. Обратные маршруты в 172.16.11.0/24 не нужны, потому что скрипт включил NAT.

Firewall → Rules → WAN. Надо разрешить tcp
Firewall → NAT → Port Forward. Надо пробросить порт до сервера
Interfaces → WAN: сними галку «Block private networks and loopback addresses»

Дальше выполняем на клиенте это:
```bash
scp root@192.168.3.1:/root/client1.ovpn ~/
```

И надо пробросить порт 1194 на сервере

Дальше создать статический маршрут, направляющий трафик до сетей первого офиса через адрес клиента и наоборот до сетей второго офиса через адрес сервера.

Дальше на сервере идем в ccd, создаем файл client1:
```bash
echo "iroute 172.16.4.0 255.255.255.0" > client1
```

Возвращаемся в server.conf:
```bash
# что добавить
route 172.16.4.0 255.255.255.0
```

И теперь финальное правило на сервере:
```bash
iptables -t nat -A POSTROUTING -s 172.16.4.0/24 -o ens3 -j MASQUERADE
```

На клиенте:
```bash
iptables -I FORWARD 1 -s 10.8.0.0/24 -o ens3 -j ACCEPT
```

Зеркально все повторить для клиента.
