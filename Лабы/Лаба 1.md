# iptables

Iptables — утилита командной строки, является стандартным интерфейсом управления работой межсетевого экрана Netfilter для ядер Linux, начиная с версии 2.4.  С её помощью администраторы создают и изменяют правила, управляющие фильтрацией и перенаправлением пакетов. Для работы с iptables нужны привилегии root'а.

Правило - состоит из критерия, счетчика и действия. Если пакет соответствует критерию, к нему применяется действие, и он учитывается счетчиком. Если критерия нет, то по умолчанию это "все пакеты". Если действия нет, то правило будет работать как счетчик. Правила для каждой цепочки срабатывают в порядке их следования.

- Критерий — логическое выражение, анализирующее свойства пакета и/или соединения и определяющее, подпадает ли данный конкретный пакет под действие текущего правила. Критерии соединяются логическим «И».
- Действие — описание действия, которое нужно проделать с пакетом и/или соединением в том случае, если они подпадают под действие этого правила.
- Счетчик — компонент правила, обеспечивающий учет количества пакетов, которые попали под критерий данного правила. Также счетчик учитывает суммарный объем таких пакетов в байтах.

Цепочка — упорядоченная последовательность правил. Цепочки можно разделить на пользовательские и базовые. Базовая - созданная по умолчанию при создании таблицы. Имена базовых цепочек всегда записываются в верхнем регистре (PREROUTING, INPUT, FORWARD, OUTPUT, POSTROUTING). Имена пользовательских цепочек всегда должны записываться в нижнем регистре.

Таблица — совокупность базовых и пользовательских цепочек, объединенных общим функциональным назначением. При вызове команды iptables таблица указывается в формате -t имя_таблицы. При отсутствии явного указания, используется таблица filter.

```bash
sudo iptables-save -c -t filter
```

Существует 5 типов стандартных цепочек, встроенных в систему:
- PREROUTING — для изначальной обработки входящих пакетов.
- INPUT — для входящих пакетов адресованных непосредственно локальному процессу (клиенту или серверу).
- FORWARD — для входящих пакетов перенаправленных на выход (заметьте, что перенаправляемые пакеты проходят сначала цепь PREROUTING, затем FORWARD и POSTROUTING).
- OUTPUT — для пакетов генерируемых локальными процессами.
- POSTROUTING — для окончательной обработки исходящих пакетов.

| Цепочка   | Что происходит                                                      | IP-пакет                                              |
| --------- | ------------------------------------------------------------------- | ----------------------------------------------------- |
| `INPUT`   | Пакет **пришёл на этот хост** и предназначен ему                    | `dst IP` — адрес этого хоста                          |
| `OUTPUT`  | Пакет **создан этим хостом**                                        | `src IP` — адрес этого хоста                          |
| `FORWARD` | Пакет **прошёл через этот хост**, который маршрутизирует его дальше | `src IP` и `dst IP` — обычно адреса **других хостов** |
Разница определяется не специальным полем в IP-заголовке, а **ролью Linux-хоста относительно пакета**:

**INPUT:** пакет предназначен _этоту компьютеру_  
**OUTPUT:** _этот компьютер_ отправляет пакет  
**FORWARD:** другой компьютер присылает пакет **этому компьютеру как роутеру**, роутер отправляет его на другой компьютер

Цепочки организованы в 4 таблицы (таблицу raw не объясняю, можно почитать [тут](https://help.ubuntu.ru/wiki/iptables)):
- mangle — содержит правила модификации (обычно заголовка) IP‐пакетов. Среди прочего, поддерживает действия TTL (Time to live), TOS (Type of Service), и MARK (для изменения полей TTL и TOS, и для изменения маркеров пакета). Содержит 5 стандартных цепочек.
- nat — просматривает только пакеты, создающие новое соединение (согласно системе определения состояний). Поддерживает действия DNAT, SNAT, MASQUERADE, REDIRECT. Содержит цепочки PREROUTING, OUTPUT, и POSTROUTING.
- filter — основная таблица, используется по умолчанию если название таблицы не указано. Содержит цепочки INPUT, FORWARD, и OUTPUT.

В системе netfilter, каждый пакет проходящий через механизм определения состояний, может иметь одно из четырёх возможных состояний:

- NEW — пакет открывает новый сеанс. Классический пример — пакет TCP с флагом SYN.
- ESTABLISHED — пакет является частью уже существующего сеанса.
- RELATED — пакет открывает новый сеанс, связанный с уже открытым сеансом.
- INVALID — все прочие пакеты.

Извне -> FW:
- **Action**: `Block`
- **Interface**: `WAN`
- **Protocol**: `Any` (или можно позже сузить)
- **Source**: `Any`
- **Destination**: `This firewall (self)`
- **Description**: `Block WAN access to firewall`
![[Pasted image 20260920140450.png]]

Разрешить трафик изнутри инфраструктуры офиса наружу (обычно настроено по умолчанию). Должны быть такие настройки:
- **Action**: `Pass`
- **Interface**: `LAN`
- **Protocol**: `Any`
- **Source**: `LAN subnet`
- **Destination**: `Any`
- **Description**: `Allow LAN to internet`

Forward-трафик извне инфраструктуры офиса вовнутрь. Ничего дополнительно делать не надо. pfSense по умолчанию не пропускает внутрь инициированные из WAN соединения внутрь. Ответный трафик на уже установленные соединения (LAN -> WAN -> ответ к LAN) будет пропущен автоматически благодаря механизму keep state.

Разрешить ICMP из WAN только до внешнего интерфейса FW. Надо создать в WAN правило перед общим блоком:
- **Action**: `Pass`
- **Interface**: `WAN`
- **Protocol**: `ICMP`
- **Source**: `Any` (или сузь до конкретных сетей/мониторинга)
- **Destination**: `This firewall (self)` (или `WAN address`)
- **ICMP subtypes**: обычно `Echo Request` (и, при необходимости, `Echo Reply`)
- **Description**: `Allow ICMP to firewall WAN interface only`

Настройка NAT: по умолчанию pfSense настраивает Outbound NAT (MASQUERADE) для LAN -> WAN, так что ничего делать не надо. Проверить можно тут:

### Действие 6 - настроить Linux-FW

```bash
# Очистить старые правила и сбросить политики

iptables -F 
iptables -X 
iptables -t nat -F 
iptables -t nat -X 
iptables -P INPUT ACCEPT 
iptables -P FORWARD ACCEPT 
iptables -P OUTPUT ACCEPT
```

Запретить входящий извне до FW (INPUT) и FORWARD извне внутрь (FORWARD):
```bash
# По умолчанию всё, что приходит к FW и через FW — дропать 
iptables -P INPUT DROP 
iptables -P FORWARD DROP 
# Исходящий трафик с самого FW — разрешить (пункт 3 для трафика "изнутри наружу" 
# здесь это трафик от сервисов на самом FW, если нужно) 
iptables -P OUTPUT ACCEPT
```

Разрешить loopback и правила для установившихся соединений (ESTABLISHED, RELATED):
```bash
# Loopback 
iptables -A INPUT -i lo -j ACCEPT 
iptables -A OUTPUT -o lo -j ACCEPT 
# Разрешить ответный трафик на уже установленные соединения 
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT 
iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT 
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT 
# Опционально: дропать INVALID 
iptables -A INPUT -m conntrack --ctstate INVALID -j DROP 
iptables -A FORWARD -m conntrack --ctstate INVALID -j DROP
```

Разрешить трафик LAN -> наружу инфраструктуры офиса:
```bash
# Разрешить инициированные из LAN новые соединения наружу (FORWARD LAN→WAN)
iptables -A FORWARD -i ens4 -o ens3 -s 172.16.1.0/24 -m conntrack --ctstate NEW -j ACCEPT
```

Правило `ESTABLISHED,RELATED` выше уже пропускает ответный трафик WAN→LAN для этих сессий.  
Это покрывает требование: **«трафик внаружу изнутри инфраструктуры должен ходить»**.

Запретить трафик извне вовнутрь и извне до FW:
- Политики INPUT DROP и FORWARD DROP это уже делают
- Дополнительно можно явно запретить новые соединения, инициированные из WAN. Сделать это можно от обратного - разрешить новые соединения только нужным подсетям:
```bash
iptables -A INPUT -i eth0 -m conntrack --ctstate NEW -j DROP # явная блокировка
sudo iptables -I INPUT 1 -s 192.168.1.0/24 -j ACCEPT # разрешить только определенный тип трафика
```
Это означает "вставить правило для цепочки INPUT от этой сети на самое первое место (дать ему наивысший приоритет)."
![[Pasted image 20260923135240.png]]

Разрешить ICMP только до внешнего интерфейса FW:
```bash
# Разрешить ICMP Echo Request (ping) извне ТОЛЬКО к самому FW на ens3 
iptables -A INPUT -i ens3 -p icmp --icmp-type echo-request -j ACCEPT 
# Опционально: разрешить Echo Reply и некоторые типы для диагностики 
iptables -A INPUT -i ens3 -p icmp --icmp-type echo-reply -j ACCEPT 
iptables -A INPUT -i ens3 -p icmp --icmp-type destination-unreachable -j ACCEPT
iptables -A INPUT -i ens3 -p icmp --icmp-type time-exceeded -j ACCEPT
```
Важно:
- Эти правила только в **INPUT** (к самому FW).
- В **FORWARD** нет правил, разрешающих `eth0 → eth1` по ICMP, поэтому ping из интернета **не дойдёт до LAN**.

Настройка NAT (разрешить outbound-соединения из LAN через один публичный IP):
```bash
iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE
```

По умолчанию эти настройки не сохраняются и слетят после перезагрузки машины. Поэтому:
```bash
apt install iptables-persistent
netfilter-persistent save # рекомендуется делать так
iptables-save > /etc/iptables/rules.v4 # можно так, если не сработало
	ip6tables-save > /etc/iptables/rules.v6 # можно так, если не сработало
```

Главное правило с iptables:
- Если есть DROP, то это DROP всего трафика по цепочке (INPUT, FORWARD, OUTPUT) на интерфейсе. Если это DROP для FORWARD, то будет дропаться весь форвардный трафик, попадающий на интерфейс.
- Чтобы разрешить трафик только от определенных сетей, нужно отдельно прописать ACCEPT именно для этих сетей для нужных цепочек (INPUT, FORWARD, OUTPUT).
