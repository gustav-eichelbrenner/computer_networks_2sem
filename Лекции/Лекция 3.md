**Особенности L2-режима:**

- Передаёт **весь Ethernet-трафик**, включая broadcast/multicast и протоколы, не являющиеся IP — удалённые сегменты объединяются в **один broadcast-домен**.
- Не требует отдельной туннельной подсети и маршрутизации — клиент/сервер фактически оказываются в **одной IP-подсети** (как физически подключённые к общему свитчу).
- Накладные расходы выше, чем у TUN (больше служебного трафика — broadcast storms, ARP-флуд через туннель при большом количестве узлов), слабее масштабируется.
- Применяется, когда нужна полная L2-прозрачность — объединение офисов в один broadcast-домен, работа legacy-приложений, требующих L2-соседства (DHCP-relay через туннель, Wake-on-LAN и т.п.).


**Особенности L3-режима:**

- Передаётся только **маршрутизируемый unicast IP-трафик** — широковещательный/мультикаст и не-IP протоколы (ARP и т.п.) не проходят.
- Требуется **маршрутизация** (routes), а не мост — клиент и сервер находятся в разных подсетях, соединённых через tun-интерфейс как через обычный router.
- Более эффективен (меньше накладных расходов) и чаще используется для site-to-site и remote-access VPN, где нужна только IP-связность.

Подключиться к заблокированному ресурсу с того, для которого он не заблокирован. VPN и proxy.

VPN-сервер - сервер, который принимает запрос и отправляет его куда-то дальше.
Proxy-сервер - тоже принимает запросы и их куда-то отправляет.
Они отличаются типом подключения. VPN - это приложение, которое позволяет создать шифрованное соединение ДО VPN-сервера. На клиенте есть tun/tap адаптер, на сервере тоже есть tun/tap адаптер. 
tun/tap инкапсулирует трафик в ethernet, дальше он идет до другого ethernet по интернету, а дальше он декапсулируется до второго tun/tap адаптера. Делает это именно VPN

У OpenVPN есть профили. Профиль ставится на сервер, а потом шарится клиенту.

Тут говорилось про routing и NAT, что эти две техники используются для работы OpenVPN. Не совсем понятно, зачем они тут нужны.

Первый способ настройки OpenVPN - скрипт. У angristan'a есть нужные техники на github. Дальше в видеолекции идет объяснение практической части, но не прям настройка вплоть до NAT. 
В настройках шифрования выбирать только AES-128-CBC, т.к. только такой тип шифрования поддерживают Микротики, с цисками все ок. 
Тип сертификата - RSA.
Все остальное оставляем по умолчанию.
По итогу скриптик даст нам профиль, по которому можно будет подцепиться к серверу.
На клиенте имя профиля лучше указать такое же, каким его дал скрипт (ну каким его вводили в скрипт)

После настройки надо на сервере перезапустить openvpn.
Если проблемы с DNS, то ipv6 dns закомментить, в ipv4 dns поставить 1.1.1.1. Файл - /etc/openvpn/server.conf
Могут быть проблемы с DNS на вашей основной машине, их возможно надо будет менять

**Особенности Linux-окружения:**

- Требуется модуль ядра **TUN/TAP** (`CONFIG_TUN`), обычно включён по умолчанию.
- Для форвардинга трафика клиентов в LAN/интернет — включить `net.ipv4.ip_forward=1` и настроить **NAT/MASQUERADE** в iptables на исходящем интерфейсе.
- Нужно явно **разрешить проходящий трафик** между `tun0`/`tap0` и физическим интерфейсом в firewall (FORWARD-цепочка).
- Конфигурация текстовая (plain-text файлы), легко версионируется и автоматизируется (скрипты), в отличие от GUI-ориентированных систем (pfSense).
