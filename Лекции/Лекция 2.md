**Туннель** — логический канал поверх другой сети. Исходный пакет помещается внутрь нового пакета, который передаётся через промежуточную IP-сеть.

Для работы туннеля нужен отдельный интерфейс. Он нужен как точка входа и выхода туннельного трафика, маршруты направляют пакеты через этот интерфейс.

GRE-туннель начинается на том роутере, который внедряет в пакет GRE-заголовок. GRE-туннель заканчивается на том роутере, который снимает с пакета GRE-заголовок.

**GRE — Generic Routing Encapsulation**, протокол инкапсуляции сетевых пакетов. GRE позволяет передавать один сетевой протокол внутри другого, обычно IP внутри IPv4.

GRE сам по себе:
- не шифрует трафик
- не обеспечивает аутентификацию
- не является полноценным механизмом защиты

## Как GRE работает

Допустим, машина A отправляет пакет через туннель машине B.

1. Пакет поступает на виртуальный интерфейс `gre1`.
2. Ядро добавляет GRE-заголовок.
3. Затем добавляется внешний IP-заголовок:
    - `source` — адрес машины A в транспортной сети;
    - `destination` — адрес машины B.
4. Получившийся пакет идёт через обычную маршрутизацию.
5. Машина B снимает внешний IP- и GRE-заголовки.
6. Исходный пакет передаётся дальше по таблице маршрутизации.

С точки зрения внешней сети пакет направляется между транспортными адресами. С точки зрения маршрутизатора внутри туннеля используются исходные адреса вложенного пакета. Это и есть инкапсуляция.

Строгое замечание: GRE — это не «магический провод» и не отдельная сеть сам по себе. Для его работы адрес удалённого конца должен быть достижим обычной маршрутизацией, а между узлами должен проходить IP-протокол GRE — номер **47**, не TCP и не UDP.

Если GRE не работает, то скорее всего на firewall'е нет access-правила для ip protocol 47.

GRE не имеет TCP/UDP-порта, поэтому разрешение на маршрутизацию надо выдавать по полю ip protocol = 47.
